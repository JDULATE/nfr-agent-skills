# Visual comparison practices

Use these practices for the agreed appearance question, not as universal style rules.

## Content-matched variants

- Use when comparing composition, surface styling, typography, or imagery.
- Trade-off: holding content and state constant isolates the intended comparison
  but does not establish appeal across other screens or audiences.
- Verify: retain rendered populated states with the same text, controls, viewport,
  data density, and asset-loading state; disclose unavoidable differences.

## Visual-dimension ledger

- Use when the proposed design changes several appearance choices together.
- Trade-off: a combined candidate can be practical, but its rating cannot identify
  which individual visual choice caused the response.
- Verify: record each changed dimension and show the actual candidate; claim a
  bundled preference only unless a further comparison isolates a dimension.

## Aesthetic prompt and order record

- Use when gathering audience judgments about the visual surface.
- Trade-off: a short anchored question is comparable but cannot explain the
  underlying preference without open comments.
- Verify: retain exact prompt, anchors, order, audience context, and reasons;
  inspect whether task-frustration language was introduced before the judgment.

## Functional preservation gate

- Use when decoration changes grouping, hierarchy, control appearance, or density.
- Trade-off: the preferred visual treatment may be constrained by recognition,
  required information, branding, and the interaction's real control states.
- Verify: inspect actual rendered states for lost controls or clipping and run
  the project's existing recognition/interaction checks; keep these results separate.
