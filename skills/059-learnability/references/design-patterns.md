# Acquisition patterns

Keep learning through product use distinct from a structured course intervention.

## Initial/practice/probe separation

- Use when acquisition rather than today's completion is the acceptance question.
- Trade-off: observing separate attempts costs time and can alter exposure;
  collapsing them hides whether assistance performed the task for the user.
- Verify: retain each attempt's inputs, help, action trace, and actual result;
  score independence only under the agreed assistance boundary.

## Product-embedded decision cues

- Use when a newcomer cannot choose between meaningful task alternatives.
- Trade-off: explaining a cue can support discovery, while an overlay containing
  the final answer can make guided completion look like acquired ability.
- Verify: rehearse with the cue, then probe the same decision without answer-bearing
  help; do not remove ordinary aids unless the protocol excludes them.

## Changed-instance transfer

- Use when repetition might be answer memorization.
- Trade-off: changing data tests transfer, but adding new prerequisites changes
  what skill is being assessed and can create an unrelated failure.
- Verify: compare required decisions across instances and inspect the new result;
  changed labels alone may still expose the same memorized answer.

## Assistance and retention ledger

- Use when users request help, receive coaching, or need ability after a delay.
- Trade-off: withholding requested help can be inappropriate for the live task;
  providing it is allowed but changes what independence evidence exists.
- Verify: retain interventions and agreed delays explicitly; classify coached
  success separately and leave delayed retention unknown without a later probe.
