# Worked example: a priority reversal with unfinished work

Assume a fictional reporting team is building an export summary. A stakeholder
changes the priority to a recipient-filter correction. The correction's expected
behavior and release checks already exist; this example asserts no legal duty.

Inspect the delivery record, relevant code, retained acceptance gates, and the
unfinished export artifacts. Record the priority change before revising the plan.
Propose: "After `{priority_decision}`, delivery shall produce `{accepted_plan}`
within `{confirmed_response_bound}`, retain `{release_constraints}`, and expose
`{paused_export_obligations}`; verify delivery separately by `{recipient_filter_cases}`."

Illustrative timing proposal: accepted revised plan within 2 working days;
confirm with the user/stakeholder. No delivery duration or actual elapsed time is
asserted by this invented sequence; the working calendar remains to be supplied.

| Observed event in the rehearsal | Evidence / acceptance implication |
| --- | --- |
| Stakeholder changes priority | Decision identity links new slice to the actual change |
| Team pauses export summary | Retained draft, open decisions, owner, restart condition |
| Correction needs a data-owner decision | Wait remains on the priority timeline |
| Revised slice drops a required recipient check | Scope/gate decision unresolved; faster planning is not success |
| Plan is accepted with retained checks | Planning response endpoint reached, not delivery endpoint |
| Correction passes the accepted recipient cases | Evidence of the new priority's delivered outcome |
| Export work resumes | Retained artifact and decisions suffice, or reconstruction cost is exposed |

Compare the original export commitment with the revised promise; identify who
accepts its displacement. Do not mark the export canceled just to hide unfinished
work. A resumed task that needs rediscovering prior decisions reveals a deficient
interruption record even if the urgent correction shipped.

Return plan-response evidence, separately observed delivery outcome, waiting, and
paused-work consequences. This example cannot establish a team's real throughput,
calendar responsiveness, or ability to react repeatedly to changing priorities.
