# Experience-response practices

Measure the feeling the user reports; do not substitute a behavioral proxy for it.

## Interaction-moment trace

- Use when comments describe frustration or preference without naming a cause.
- Trade-off: linking comments to moments narrows a candidate change but does not
  prove that moment caused the whole subjective response.
- Verify: connect the stated reason to an actually experienced flow state and
  inspect the proposed change there; keep causal explanations provisional.

## Neutral post-experience prompt

- Use when collecting subjective responses after a specified task.
- Trade-off: an anchored question permits comparison but can lose nuances;
  open reasons add context without converting opinion into a task oracle.
- Verify: preserve the wording and anchors, avoid praising the candidate, and
  record negative, neutral, unanswered, and positive responses distinctly.

## Equivalent-exposure comparison

- Use when comparing preferences between interaction alternatives.
- Trade-off: holding the goal constant improves interpretability; differences
  in error states, assistance, or exposure order can still shape the response.
- Verify: record actual task states and order for each condition and disclose
  differences; do not attribute every preference to the changed interaction.

## Dual evidence ledger

- Use when task success and reported feeling disagree.
- Trade-off: separate ledgers resist a convenient single verdict, but preserve
  the distinction needed to improve sentiment without hiding performance problems.
- Verify: store the task result beside the response and reason; neither overwrites
  the other, and silence or compulsory reuse never becomes a positive rating.
