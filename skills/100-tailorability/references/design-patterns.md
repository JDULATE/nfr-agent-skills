# Fitting supported behavior to a context

The stakeholder supplies needs and priorities. Choice availability, contextual
fit, and live transition are separate claims even when one implementation supports all.

## Need-to-choice matrix

- **Use when:** A team has task constraints that existing options may satisfy.
  Connect each need to its supported choice, prerequisite, task, and result oracle.
- **Trade-off:** A convenient preset may satisfy preferences but miss a must-have;
  more options do not compensate for the missing required result.
- **How to verify:** Run each confirmed must-have task under the selected recipe
  and retain unsupported needs rather than quietly deleting them from coverage.

## Scoped recipe and shared obligations

- **Use when:** Contexts need different supported arrangements. Record scope and
  effective precedence alongside shared outputs that cannot change just for local fit.
- **Trade-off:** A global default is simpler to edit but can break another context;
  a local override may depend on a scope selector the user has not actually confirmed.
- **How to verify:** Recreate the local recipe from declared starts, run its tasks,
  and compare an unaffected context with its accepted baseline result.

## Gap versus new stakeholder behavior

- **Use when:** A requested context need cannot be expressed by existing choices.
  Record the gap and distinguish a priority change from separately scoped authorship.
- **Trade-off:** Relaxing a need may make fitting feasible but changes the acceptance
  context; adding a hidden bespoke patch makes the recipe no longer supported-choice fit.
- **How to verify:** Supply the unsupported request, inspect the explicit gap decision,
  and reject any claimed complete fit that depends on undocumented custom code.

An illustrative fit target is 0 unmet agreed must-haves on the selected context fixtures;
confirm with the user/stakeholder. This does not establish exhaustive stakeholder
coverage. Ask the user which needs are mandatory, which are preferences, and who
can accept trade-offs before treating an existing preset as a solution.
