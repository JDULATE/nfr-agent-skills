# Examining a report approval

The fictional review asks whether `report-slate` was approved under the recorded
exception policy during the named review scope. The examiner may see the approved
evidence view, not raw credentials or unrestricted personal records.

## Inputs and answer state

Evidence contains an approval event, its policy revision, a linked exception,
and a collection-gap marker affecting part of the scope.

| Input evidence | Supported examination output | Carried limitation |
| --- | --- | --- |
| Approval event with source/revision | The recorded action can be examined | Actor attribution depends on its identity evidence |
| Policy and exception context | Compare decision with supplied rule | No invented external obligation |
| Collection gap | Relevant missing interval remains unknown | Empty query cannot prove no exception |
| Favorable export omits exception | Package is insufficient | Contradictory material must remain retrievable |
| Reviewer lacks required interpretation context | Question not independently answerable | Author explanation alone is not examiner access |

## Proposed answer gate

Illustrative example; confirm with the user/stakeholder:
Allow 0 unsupported affirmative conclusions in the agreed normal, gap and
contradictory-evidence fixtures. Ask for exact question, retention and permitted view.

## Repository work and verification

Map the question to actual records and provenance, expose the approved context,
and make collection status visible beside the retrieved events. Reproduce the
answer under the intended review role. An event file can exist and still leave
part of the question unanswerable; a typed artifact link does not evaluate it.
This is a synthetic examination protocol, not a completed audit or compliance finding.
